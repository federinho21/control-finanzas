# Module 6 — Private uploads and RAG

## Implemented

- POST `/api/upload` requires cookie authentication and Origin, accepts exactly one multipart file, caps the request at 6 MB and file at 5 MB, and ignores no client-owned identifiers: extra fields are rejected. Document IDs are generated by the server.
- PDF signature/MIME, UTF-8 text, binary bytes and filenames are checked. Formats are PDF, TXT, CSV and existing Markdown. PDF extraction allows at most 20 pages; readable text is capped at 150,000 characters and 150 chunks. Upload quota is five requests/hour/UID; storage metadata quota is 100 documents/UID, transactionally checked.
- Originals and extracted text use private Storage paths `users/{uid}/documents/{id}/{original,extracted.txt}`. No public URLs or download tokens are generated. Proposed `storage.rules` deny all direct client access; the Admin identity needs bucket-scoped IAM.
- Firestore metadata/chunks live only under `users/{uid}`. Processing/failed/deleting/expired documents are excluded from RAG. Embeddings are bounded finite numeric arrays with consistent dimensions; incompatible query vectors are not compared.
- Approving a plan links its provisional document in the finance transaction. Another user's document aborts the entire approval. DELETE `/api/documents/{id}` cannot cancel linked documents or active processing. Retry after a Storage deletion failure is safe; the document remains non-searchable.
- Failed processing cleans objects where possible, retains failed metadata for investigation, and creates no searchable chunks. No startup/shutdown global cleanup runs.
- Owner-scoped, reviewed orphan cleanup is available with `npm run cleanup:documents`. It defaults to dry-run and requires project, UID, bucket and a matching confirmation hash to delete expired provisional records. Linked documents are rechecked and rejected inside the deletion transaction.

## Configuration and checks

Set `FIREBASE_STORAGE_BUCKET` to the actual bucket name, not an assumed suffix; use ADC locally and runtime service-account IAM in App Hosting. Do not expose service-account credentials to the browser. `NUXT_GEMINI_API_KEY`/local `GEMINI_API_KEY` enables embeddings and AI; it is a secret.

```powershell
npm run test:finance
npm run typecheck:finance
npm run cleanup:documents -- --uid OWNER_UID --project PROJECT_ID
# Only after reviewing the dry-run IDs/hash:
npm run cleanup:documents -- --uid OWNER_UID --project PROJECT_ID --bucket BUCKET --apply --confirm-hash REVIEWED_HASH
```

Emulator tests use deterministic test embeddings and an in-memory file adapter, NOT the live Storage service. Tests cover A/B search/summary/delete isolation, document linking, immutable linked documents, malformed uploads, failed embeddings and distributed quotas. Browser auth regressions pass, but actual multipart upload and real PDF/Storage behavior were not browser-tested.

## Limits and release gates

RAG searches the latest 300 ready chunks per owner, with a batched metadata read; it is not an exhaustive large-library search. Add Firestore vector indexes before increasing library scale. Documents are untrusted evidence; prompt instructions do not replace code authorization. PDF parsing is in-process and has no malware scanner or worker isolation; dependency remediation and representative PDF stress tests are release gates. Expired documents are excluded immediately but physical removal requires running the owner-scoped cleanup; no scheduler was deployed. Windows snapshot/file permissions need operator review.
